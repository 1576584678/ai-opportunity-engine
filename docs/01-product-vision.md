# 01 产品愿景与定位

## 1. 要解决的问题

企业在考虑 AI 落地时,普遍卡在三件事上:

1. **不知道从哪下手。** 能想到的都是通用场景(客服、写作),和自己真实业务链条上的高价值环节对不上。
2. **判断不了值不值得做。** 缺行业成本基准和收益基线,立项时讲不出可信的账,做完了也不知道有没有效果。
3. **方案与落地脱节。** 拿到的方案是「正确的废话」——没有流程改动点、没有数据要求、没有集成方式、没有验收指标。

## 2. 产品定位

**一句话:** 把非结构化的业务描述,转成结构化、可算账、可执行的 AI 机会地图与落地方案。

**产品形态:** 不是聊天机器人,而是一条工程化流水线 —— 采集 → 业务建模 → 机会点生成 → 打分排序 → 方案细化 → 交付物渲染。

**关键立场:** 输出必须可被质疑和追溯。每个数字都要能点开看到计算过程与假设来源。

## 3. 目标用户

### 3.1 主用户(付费方)

| 用户 | 场景 | 付费动机 |
| --- | --- | --- |
| 咨询公司 / 数字化咨询顾问 | 售前方案、诊断报告 | 把 3 天的方案撰写压缩到 3 小时 |
| 系统集成商 / 软件 ISV | 售前报价、方案匹配 | 提高方案命中率,缩短销售周期 |
| 企业数字化服务商 | 批量诊断客户 | 人均产能提升,降低交付成本 |

### 3.2 次用户(使用方,非直接付费方)

- 中大型企业 IT / 数字化部门:用于内部立项与向上汇报的初稿,是辅助工具不是决策依据。
- 终端中小企业:通过渠道触达,一般不直销。

### 3.3 明确不做

- 不做纯 C 端或小微企业自助版(付费意愿弱、流失高、支持成本高)。
- 不做「输入一句话生成商业模式」这类空转功能。
- 不在早期做多行业通用版,前 3 个行业必须做深。

## 4. 用户旅程

1. **采集** —— 自由文本描述 + 引导式问卷(行业、规模量级、业务域、系统清单、数据现状、痛点、现有 KPI)。
2. **业务建模** —— 抽取为结构化模型:业务域 → 流程节点 → 角色 → 系统 → 数据源 → KPI → 量级。
3. **机会点生成** —— 用「AI 能力 × 流程节点」矩阵穷举候选,再做适用性过滤。
4. **打分排序** —— 价值 / 可行性 / 成本 / 风险 四维打分,输出优先级队列。
5. **方案细化** —— 对 Top N 生成改造前后流程、技术方案、数据接入、Agent 设计、集成方式、里程碑、验收指标、风险与合规。
6. **交付** —— 机会地图、方案文档、路线图、预算表、PoC 实验设计。

## 5. 价值主张

| 对谁 | 价值 |
| --- | --- |
| 咨询顾问 | 方案产出效率提升 5-10 倍,且质量下限被方法论托住 |
| 集成商 | 售前周期缩短,方案可执行性提高,赢单率提升 |
| 企业 | 拿到能立项的方案,而不是 PPT 里的概念 |
| 平台自身 | 沉淀行业基准数据与效果反馈,形成数据飞轮 |

## 6. 差异化定位

- **方法论约束,而非自由发挥。** 机会点是穷举后筛出来的,不是模型想到几个算几个。
- **确定性计算。** 成本与 ROI 由代码计算,不让模型做算术。
- **可追溯。** 所有量级标注来源(用户提供 / 行业基准 / 假设)与置信度。
- **合规前置。** 红线项一票否决,不参与排序。
- **交付闭环。** 方案可导出为文档,并可进一步生成 PoC 与 Agent 编排。

## 7. 成功指标(概览)

详细定义见 `09-risks-and-metrics.md`。

- 北极星:每月产出并进入「落地阶段」的方案数。
- 核心质量指标:方案被客户采纳的环节数 / 生成环节数(采纳率)。
- 商业指标:付费席位增长、单客户年价值(ACV)、方案到项目的转化率。
