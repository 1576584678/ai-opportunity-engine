# 03 市场与竞争分析

## 1. 需求侧的现实

- 企业 AI 正在从 PoC 走向生产,预算真实存在,决策从「要不要用 AI」变成「先做哪个」。
- 但绝大多数企业的瓶颈不是模型能力,而是**识别场景、算清收益、组织落地**这三件事。
- 需求真实,且时间点正确 —— 这是本产品成立的前提。

## 2. 竞争格局

| 竞争者 | 形态 | 优势 | 对我的影响 |
| --- | --- | --- | --- |
| 通用大模型(直接对话) | 免费 | 生成速度快、质量下限不断提高 | **最大威胁**:会持续抹平「生成方案」这一层 |
| 云厂商诊断工具 | 免费获客 | 算力/模型背书、渠道强 | 挤占终端企业诊断入口 |
| 头部咨询公司 | 人力密集 | 品牌信任、交付能力 | 客单价高,走大客户;但自建内部工具 |
| 管理软件厂商 | 嵌入现有系统 | 有客户系统与数据 | 可能把诊断做成软件标配功能 |
| 同类创业工具 | 产品 | 灵活 | 尚无明确领跑者,窗口期存在 |

## 3. 差异化定位(避开正面战场)

**核心策略:打竞争者服务不到或不愿服务的缝隙。**

1. **卖方的售前提效,而不是买方的决策依据。** 咨询/集成商每天都要写方案,这是高频、可量化、决策快的需求,而云厂商和通用模型都不专门服务它。
2. **行业纵深而非行业广度。** 前 3 个行业做深(场景库 + 成本基准 + 案例),不追求「什么行业都行」。
3. **可追溯的算账能力。** 所有数字标注来源与置信度,这是通用模型不会做的事,也是乙方方案能否过评审的关键。
4. **交付闭环。** 方案能直接转成 PoC 与 Agent 编排,而非停在 PPT。

## 4. 威胁与应对

| 威胁 | 应对 |
| --- | --- |
| 通用模型能力提升导致生成层被抹平 | 价值重心持续向「私有基准数据 + 交付闭环」迁移 |
| 云厂商免费工具 | 不正面竞争,做其生态内的卖方工具,甚至上架到其市场 |
| 客户自建 | 用知识库更新速度与行业深度保持领先;接受部分客户流失 |
| 数据难获取,ROI 不准 | 用「区间 + 假设标注」替代单点数字,并持续用真实项目校准 |

## 5. 时机判断

- **有利:** 企业 AI 预算处于从试点到规模化的过渡期,「先做哪个」的决策需求集中爆发。
- **不利:** 供给端同步爆炸,生成类能力快速商品化。
- **结论:** 窗口期存在但短。**先验证付费,再决定投入深度**,不要以产品为起点。

## 6. 需要持续跟踪的信号

- 通用模型在「结构化商业方案生成」上的质量跃迁速度。
- 云厂商诊断工具是否开始收费或能力下探到售前场景。
- 集成商是否开始批量采购 AI 相关售前工具。
