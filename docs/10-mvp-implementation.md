## 2. 与文档的工程偏差(需要评审)

### 2.1 风险 R 的归一化与责任因子取向(已回写文档,不再是偏差)

原 `04 §5.4` 的 `R = 幻觉影响面 × 合规等级 × 责任归属清晰度` 有两个问题:

1. 三项各取 1-5 时 `R` 动态范围 1-125,而同处分母的 `C` 以「元」计,排序会被 R 单独主导。
2. 「责任归属清晰度」5 分表示责任清晰,直接相乘反而抬高风险,取向与业务含义相反。

实现改为 `R = (幻觉影响面 × 合规等级 × (6 - 责任归属清晰度)) ** (1/3)`:几何平均把量纲拉回 1-5
与 V、F 可比,责任因子取反向。**`04 §5.4` 与 §5.5 已按此口径重写**,代码与文档一致,无需再评审差异。

### 2.2 可行性判定按「单项 < 0.3」

`04 §5.2` 原文是「任一项 < 0.3 时整体判为暂不可行」。实现严格按此执行:
`F = 四项之积` 仍作为排序用的连续值,但**排除资格**只看单项是否低于阈值,不看乘积。

### 2.3 数字隔离用显式登记表

`06 §6` 要求「量级与收益数字由系统注入,模型不生成数字」。实现落地为一个数字登记表:
方案正文里每个数字都必须经 `NumberRegistry.reg()` / `reg_text()` 登记,
S8 自检反向扫描正文,发现未登记数字即打回。客户提供的原文(如 KPI 现值)通过 `reg_text()` 登记。

这条约束在换成 LLM 撰写后价值最大——它把「不许编数字」从 Prompt 里的软约束变成了机器判定。

边界要说清楚:**客户原文里的数字属于客户提供,不属于模型生成。** 模板组装把痛点、角色、触发条件、
输入输出、数据载体、合规整改建议这些客户/KB 原文拼进方案时,必须先用 `reg_text()` 整段登记。
否则客户自己说的「去年漏检 12 次、损失 84 万元」会被 S8 判成模型编造——这是过严,不是安全。
相对的,LLM 路径下模型自己写的文字**永远不登记**,只做反向扫描。

### 2.4 机会点去重与合并的 MVP 形态

`04 §3` step 4 要求「同源机会点合并为一个方案」。MVP 的实现是:
同一流程节点最多产出 1 个方案(`MAX_PLANS_PER_NODE = 1`),排序仍展示该节点的全部候选。

### 2.5 业务画像用扁平节点列表

`06 §3` 的示例 Schema 把节点嵌套在业务域下。实现改为扁平的 `nodes[]`,每个节点自带 `domain` 字段——
这与 `05 §4` 的 `process_node` 表结构一致,且便于按节点检索与打分。

### 2.6 真实模型路径的实测(S2 / S7)

已用本机 vLLM 端点(见 `.env.example`)跑通两条 LLM 路径,结论按 `06 §4` 的可验证标准记录:

- **S2 抽取**:模型在客户未提供的字段上正确输出 `missing`,没有编造数字;补 `--hints-file` 后画像无缺项。
- **S7 撰写**:`--composer llm` 连跑三次方案,S8 十项自检 **3/3 通过**。
- 撰写循环里只对「未登记数字」和「未绑定流程节点」两类问题自动打回重写,
  其余自检项只记录不改写,避免模型为了过检而软化事实。
- `05 §7` 要求的事实来源约束因此变成可机器判定的闸门:模型输出一律**不**登记进 `NumberRegistry`。

实测中修复的两个真实缺陷(已补回归测试):

1. `04 §5.4` 排他性检查里集成方式按字面匹配,模型常写「RPA自动化」而标签是「RPA 自动化」,
   空格差异导致误判。现比较前统一去空白。
2. 自检项一原先只在 `before_process`/`after_process` 里找节点名,模型改写节点名即误判。
   现在扫描方案全文,并把失败反馈进 S7 重写循环,由模型自行改回逐字引用。

## 3. 运行

```bash
pip install -e ".[dev]"

# 校验画像
python -m aoe validate data/profiles/retail_ecommerce_demo.json

# 跑完整流水线
python -m aoe run data/profiles/retail_ecommerce_demo.json --out outputs/report.md

# 测试
python -m pytest
```

推荐一律使用 `python -m aoe`:它不依赖 `PATH` 配置,也不受企业应用控制策略对 `.exe` 启动器的限制。
安装后同时会生成 `aoe` 控制台脚本,脚本目录在 `PATH` 上时可直接用 `aoe`。
未安装包时可用 `$env:PYTHONPATH="src"`(Windows)或 `PYTHONPATH=src`(POSIX)配合 `python -m aoe`。

知识库目录默认从仓库根的 `data/` 查找,私有化部署时可用环境变量 `AOE_DATA_DIR` 覆盖。

## 4. 输出物

- `outputs/<公司名>-report.md`:主报告(结论摘要 / 机会地图 / 排除清单 / 方案 / 自检 / 缺口)。
- `work/runs/<run_id>/`:各阶段中间态 JSON,支持重跑与对比(`05 §7` 的可回放要求)。
