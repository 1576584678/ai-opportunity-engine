# 08 路线图与里程碑

## 1. 总体原则

**先验证付费,再写代码。** M0 不做产品。

## 2. 里程碑

### M0 需求与付费验证(1-2 周)

- 交付物:手工制作的 3-5 份方案(用现成模型 + 自制模板人工交付)。
- 只验证三个数:有没有人付钱 / 付多少 / **是否愿意为落地再付钱**。
- 通过标准:至少 2 家付费;且至少 1 家明确表示为落地付费。
- 不通过则回到 `02-business-model.md` 重新选路径,不进入 M1。

### M1 方法论与知识库奠基(2-3 周)

- 交付物:`04-core-methodology.md` 的量表落地为可执行的规则表;3 个行业的冷启动知识库。
- 交付物:业务画像 JSON Schema 与人工填报模板。
- 通过标准:人工用该 schema 处理 5 个真实客户,画像完整度 ≥ 80%。

### M2 MVP 产品化(4-6 周)

- 范围:
  - 引导式问卷 + 自由文本采集,含缺口追问
  - 业务建模(结构化输出 + 校验)
  - 候选机会点生成 + 规则过滤(不含复杂 RAG)
  - 评分引擎(代码实现,含敏感性分析)
  - Top 3 方案生成 + Critic 自检
  - 导出 Markdown / Word
- 不做:系统对接、文件解析、协作、PPT 导出、多行业通用。
- 通过标准:端到端跑通 1 个目标行业;3 位目标用户试用,采纳率(被采纳环节数/生成环节数)≥ 40%。

### M3 工作台与商业化(4-6 周)

- 范围:方案工作台(编辑、版本、对比)、模板库、PPT 导出、租户与配额、私有化部署包。
- 通过标准:签约 ≥ 5 家卖方客户,续费率可观测。

### M4 闭环与飞轮(持续)

- 范围:落地度评估、PoC 与 Agent 编排生成、供应商匹配、`outcome` 回填与基准校准。
- 通过标准:首批项目的「预期 vs 实际」数据入库,评分精度有可量化提升。

## 3. 迭代路线

| 期次 | 主题 | 关键能力 |
| --- | --- | --- |
| 一期 | 可用 | 画像 → 机会点 → 方案,单行业 |
| 二期 | 好用 | 工作台、模板库、导出多格式、多行业 |
| 三期 | 能落地 | 系统对接评估、生成 PoC 与 Agent、供应商匹配 |
| 四期 | 会学习 | 效果回收、基准校准、评分自优化 |

## 4. 资源估算(假设)

| 项 | M2 MVP | 说明 |
| --- | --- | --- |
| 后端 + 编排 | 8-10 人日 | FastAPI + DAG + 模型接入 |
| 前端 | 8-12 人日 | 采集与工作台 |
| 方法论与规则表落地 | 5-8 人日 | 评分模型与合规规则 |
| 知识库冷启动 | 10-15 人日 | 3 个行业,最大的隐性成本 |
| 模型调用费 | 数百元/月 | 验证期量级 |

**最大风险项是知识库冷启动的人力投入**,不是代码量。若无法投入这部分人力,项目不应启动。

## 5. 团队配置建议

- 1 名产品/方法论负责人(必须具备咨询或企业数字化背景)
- 1 名全栈工程师
- 1 名行业专家(兼职即可,M1-M2 关键)

**缺少行业专家是 M2 失败的最常见原因。**
