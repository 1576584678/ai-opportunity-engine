# 04 核心方法论

这是本产品最核心的资产,也是与「直接问大模型」的根本区别。

## 1. 业务画像模型(结构化中间层)

所有下游能力都建立在这张结构上。字段定义:

| 实体 | 关键字段 |
| --- | --- |
| 业务域 | 名称、重要性权重、当前人力投入 |
| 流程节点 | 所属业务域、触发条件、输入、输出、执行角色、系统、耗时、频次、量级、当前痛点 |
| 角色 | 名称、人数、职责、技能门槛 |
| 系统 | 名称、类型(自研/采购/SaaS)、是否有 API、数据可导出性 |
| 数据源 | 名称、载体、格式、更新频率、是否含个人信息、可得性评级 |
| KPI | 名称、当前值、目标值、归属流程节点 |
| 量级参数 | 人数、单量、客单价、单次耗时、人力成本 —— **ROI 计算的必要输入** |

**硬性规则:** 量级参数缺失时必须向用户追问,**禁止编造**。所有数值必须标注来源:`用户提供 / 行业基准 / 假设`。

## 2. AI 能力目录

能力按「可交付的输出形态」分类,便于与流程节点做匹配:

| 类别 | 典型能力 | 可自动化系数区间 |
| --- | --- | --- |
| 信息抽取 | 单据解析、结构化录入、文档信息提取 | 0.8 - 0.95 |
| 内容生成 | 文案、报告、回复草稿、代码 | 0.6 - 0.9 |
| 分类与判定 | 意图识别、风险分级、异常检测 | 0.7 - 0.9 |
| 预测与推荐 | 需求预测、定价建议、人群推荐 | 0.4 - 0.7 |
| 问答与检索 | 知识库问答、政策查询、内部检索 | 0.7 - 0.9 |
| 编排与执行 | 多步 Agent、跨系统操作、RPA 增强 | 0.3 - 0.6 |
| 感知类 | 视觉质检、语音转写、图像识别 | 0.5 - 0.85 |
| 物理动作 | 需要实体作业的环节 | 0.05 - 0.2 |

## 3. 机会点生成矩阵

**方法:穷举 → 过滤 → 排序。**

1. **候选生成:** 将 `AI 能力目录` × `流程节点` 做笛卡尔积,得到全部候选机会点。
2. **适用性过滤(规则):**
   - 数据不可得或不可导出 → 剔除
   - 流程未标准化、每次做法都不同 → 降级为「需先标准化」
   - 命中合规红线 → 剔除并单独列出
3. **能力匹配:** 用知识库中的行业场景案例做相似检索,为候选补充「同行怎么做的」。
4. **去重与合并:** 同源机会点合并为一个方案。

## 4. 可自动化系数

**定义:** 该环节工作量中可被 AI 替代或显著加速的比例(0-1)。

**取值依据(按顺序判断):**

1. 输出是否为纯数字/文本资产?(是 → 基础值 0.8)
2. 是否需要人工做最终判断/承担后果?(是 → ×0.7)
3. 是否依赖专有数据或隐性经验?(是 → ×0.7)
4. 是否涉及物理动作或线下场景?(是 → ×0.3)
5. 是否有强合规审查要求?(是 → ×0.8)

**注意:** 系数默认取保守值。宁可低估收益,也不要高估。

## 5. 评分模型

### 5.1 价值 V

```
V = 效率收益 + 收入收益 + 风险降低收益

效率收益 = 环节 FTE × 该环节耗时占比 × 可自动化系数 × 人力成本(年)
收入收益 = 转化率提升 × 客单价 × 年单量 × 折减系数(默认 0.5,收益保守化)
风险降低收益 = 年风险事件频率 × 单次事件损失 × 预期降幅
```

### 5.2 可行性 F

```
F = 数据可得性 × 流程标准化度 × 系统可接入性 × 组织意愿
```

每项 0-1,来源于业务画像中的字段与问卷答案。**任一项 < 0.3 时整体判为「暂不可行」**,不进入优先级排序。

### 5.3 成本 C

```
C = 建设成本(人日 × 人日单价)
  + 运行成本(调用量 × 单价,按分层模型估算)
  + 维护成本(标注、运维、迭代)
```

### 5.4 风险 R

```
R = (幻觉影响面 × 合规等级 × (6 - 责任归属清晰度)) ** (1/3)
```

- 幻觉影响面:输出错误的后果严重度(1-5)
- 合规等级:是否涉及个人信息、行业监管(1-5)
- 责任归属:出错后责任是否清晰(1=不清晰,5=清晰)。越清晰风险越小,故乘积中取其反向因子 `6 - 清晰度`

三项因子各取 1-5,直乘的动态范围是 1-125。而 §5.5 中 R 与「元」量纲的成本 C 同处分母,
范围过大会让 R 单独主导排序,量纲上不可比。因此取几何平均归一化回 1-5:公式形状与单调性不变,
但可与 V、F、C 放在同一个式子里比较。

### 5.5 优先级

```
优先级得分 = (V × F) / (C × R)
```

量纲约定:V、C 为元/年,F 为 0-1 的无量纲积,R 为归一化后的 1-5。四项只做乘除,不做加权求和。

**合规红线一票否决:** 命中红线的机会点直接排除出排序,单独输出并提示整改前提。

**规则:**

- 得分相同看 V;C 相同看回收周期。
- 最终排序必须展示计算明细,不可只给一个结论分。

## 6. ROI 计算规范

- 全部使用代码计算,禁止模型做算术。
- 输出形式:**区间**(悲观 / 中性 / 乐观),不用单点数字。
- 每个输入量必须带来源标签与置信度(高/中/低)。
- 必须输出回收周期与敏感性分析(哪一项假设变化对结论影响最大)。

## 7. 确定性 vs 生成 的边界

| 交给代码(确定性) | 交给模型(生成性) |
| --- | --- |
| 评分、排序、成本核算、ROI 区间 | 业务画像抽取、候选机会点的语义匹配、方案文字撰写 |
| 合规规则判定 | 行业案例检索与类比 |
| 优先级队列计算 | 集成方式建议、验收指标起草 |
